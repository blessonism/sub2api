# brainstorm: Token 用量自动分组倍率

## Goal

基于用户最近 7 天或最近 30 天的 Token 使用量，自动给用户在指定分组下分配专属计费倍率，或同时把用户授权到目标分组，并提供一个管理员页面来配置规则、查看命中用户、执行或预览分配结果。

## What I already know

- 用户希望按近期 Token 用量自动分配某个分组的专属倍率，窗口至少包括最近 7 天和最近 30 天。
- 现有系统已经有管理员用量统计、用户消耗排行榜、用户分组统计和用量日志聚合能力。
- 现有系统已经存在 `(user_id, group_id) -> rate_multiplier` 的用户专属分组倍率表与接口。
- 管理员分组页已有手动维护“分组下用户专属倍率”的弹窗，当前能力是按分组手动添加用户并批量保存倍率。
- 管理员希望在分组倍率管理中支持“选中多个条目，输入一个统一倍率，一键应用”，而不是只能逐个调整。
- 用量日志里的 Token 统计口径多处使用 `input_tokens + output_tokens + cache_creation_tokens + cache_read_tokens`。
- 计费链路会优先使用用户在当前分组下的专属倍率；没有专属倍率时使用分组默认倍率。
- 本需求的 Token 阈值口径已确认：输入 Token + 输出 Token + 缓存创建 Token + 缓存读取 Token，并只统计成功落账请求。

## Assumptions (temporary)

- 规则动作需要支持管理员配置：既可以只维护用户在目标分组下的专属倍率，也可以同时把用户授权到目标分组。
- 自动规则应由管理员配置，不能对普通用户开放。
- 最近 7 天/30 天应优先按滚动窗口计算，而不是自然周或自然月。
- MVP 优先支持按 Token 阈值映射到倍率，例如 `>= 1,000,000 tokens -> 0.9x`。
- 每条策略需要支持管理员配置执行频率，并支持页面上的手动预览与立即执行。
- 规则结构采用“一个策略内多个有序档位”：系统按用户 Token 用量命中的最高档位执行，避免多条独立规则互相覆盖。
- 目标分组放在策略层配置；档位层只配置 Token 阈值和倍率。选择“授权分组并设置专属倍率”时，命中用户会被授权到该策略的目标分组。
- 管理员可为策略配置“自动规则优先”或“手动设置优先”；默认使用手动设置优先。
- Token 用量统计范围由策略配置筛选条件决定；默认不筛选，即全站总用量。
- 同一目标分组同一时间只允许一条启用中的自动策略，避免多策略同时覆盖同一用户同一分组。

## Open Questions

- 当前需求已收敛，暂无阻塞开放问题。

## Requirements (evolving)

- 管理员可以创建、编辑、启停 Token 用量分组倍率规则。
- 规则至少包含统计窗口、Token 阈值、目标分组、目标倍率、执行动作和执行频率。
- 启用策略时，同一目标分组不能存在另一条启用中的自动策略；如存在应拒绝启用或保存。
- 规则包含冲突处理策略：
  - 手动设置优先：默认值。管理员手动改过用户专属倍率或分组授权后，自动规则后续不再覆盖该用户对应配置。
  - 自动规则优先：规则执行时可继续按命中档位覆盖自动管理范围内的用户配置。
- 规则包含统计筛选范围：
  - 默认统计用户全站总 Token 用量。
  - 管理员可以按分组、模型、请求类型、计费类型等条件限制统计范围。
  - 筛选范围只影响用户是否命中档位，不改变最终写入的目标分组和倍率。
- Token 阈值统计口径固定为输入 Token + 输出 Token + 缓存创建 Token + 缓存读取 Token。
- Token 阈值只统计成功落账请求，避免失败请求影响档位。
- 每条策略包含多个按 Token 阈值升序或降序排列的档位。
- 每条策略固定一个目标分组；每个档位只配置最小 Token 阈值和该档位对应的专属倍率。
- 系统执行时为每个用户选择命中的最高档位；未命中任何档位时按自动回退逻辑清除该策略产生的配置。
- 自动降档时从当前高档退到用户当前用量对应的低档，不需要多条规则之间再做冲突优先级判断。
- 执行频率由管理员配置，至少支持每 6 小时、每天、每周等常见周期。
- 启用规则后系统按配置频率自动执行，并记录上次执行时间、下次执行时间和执行状态。
- 管理员可以在页面手动预览规则影响范围；预览只返回将新增、更新、降档、清除的用户列表，不写入数据库。
- 管理员可以在页面手动立即执行规则；立即执行与定时执行使用同一套计算和写入逻辑。
- 同一规则不能并发执行，避免重复写入或执行结果相互覆盖。
- 执行动作支持两种模式：
  - 仅设置专属倍率：只写入用户在目标分组下的专属倍率，不改变用户可访问分组。
  - 授权分组并设置专属倍率：把用户加入/授权到目标分组，同时写入该分组下的专属倍率；MVP 不删除用户已有旧分组。
- 系统可以按规则计算用户最近 7 天或 30 天 Token 用量，并生成命中结果。
- 管理员页面可以查看规则、命中人数、最近执行状态和受影响用户。
- 系统执行规则时应写入用户在目标分组下的专属倍率。
- 选择“授权分组并设置专属倍率”时，应通过现有用户 allowed groups 能力授予目标分组访问权。
- 用户后续用量低于当前档位阈值时，系统应自动降档；低于最低档或不再命中任何规则时，应自动清除该规则产生的专属倍率/分组授权。
- 自动降档或清除只能处理由自动规则产生的配置，不能误删管理员手动设置的专属倍率或分组授权。
- 自动写入不能破坏现有 RPM override 或其它用户专属配置。
- 管理员应能预览影响范围，避免错误规则一次性影响大量用户。
- 管理员可以在手动分组倍率管理中勾选多个条目，输入同一个倍率并一次性应用到所有选中条目。
- 手动批量统一倍率的输入必须是数字、必须大于 0，且最多保留两位小数；暂不设置倍率上限。
- 手动批量统一倍率应按全部成功或全部失败处理，未选中的条目不能被修改。

## Acceptance Criteria (evolving)

- [ ] 管理员能配置至少一条“最近 7 天/30 天 Token 阈值 -> 分组专属倍率”的规则。
- [ ] 同一目标分组同一时间只能启用一条自动策略。
- [ ] 管理员能选择规则动作：仅设置专属倍率，或授权分组并设置专属倍率。
- [ ] 管理员能配置规则执行频率，规则会按频率自动执行。
- [ ] 管理员能配置冲突处理策略，默认手动设置优先。
- [ ] 管理员能配置统计筛选范围；不配置时按全站总用量统计。
- [ ] 规则使用输入、输出、缓存创建、缓存读取四项 Token 之和判断档位。
- [ ] 规则不把失败或未落账请求计入 Token 阈值。
- [ ] 筛选范围只影响用量聚合和档位命中，不会隐式改变目标分组。
- [ ] 手动设置优先时，自动规则不会覆盖管理员手动接管的用户倍率或分组授权。
- [ ] 自动规则优先时，规则执行可按命中档位覆盖自动管理范围内的配置。
- [ ] 管理员能手动预览规则影响范围，预览不会写入任何用户配置。
- [ ] 管理员能手动立即执行规则，立即执行会产生与定时执行一致的变更和执行记录。
- [ ] 系统能正确聚合指定窗口内每个用户的 Token 总量。
- [ ] 命中规则的用户会获得目标分组下的专属倍率。
- [ ] 选择授权分组模式时，命中用户会获得目标分组访问权。
- [ ] 选择授权分组模式时，不会删除用户已有旧分组。
- [ ] 用户用量下降后会自动切换到对应低档倍率。
- [ ] 用户不再满足任何档位后，系统会清除自动规则产生的专属倍率/分组授权。
- [ ] 自动清除不会删除管理员手动维护的用户专属倍率或分组授权。
- [ ] 未命中用户不会被错误写入或覆盖。
- [ ] 管理页面展示规则、命中用户和执行结果。
- [ ] 执行结果有可追溯记录，便于排查和回滚。
- [ ] 管理员能勾选多个手动分组倍率条目，输入一个大于 0 且最多两位小数的倍率，并一键统一应用。
- [ ] 手动批量统一倍率拒绝空值、非数字、0、负数和超过两位小数的输入。
- [ ] 手动批量统一倍率只更新选中条目，未选中条目保持原倍率。
- [ ] 手动批量统一倍率出现校验或写入失败时，不产生部分成功的模糊状态。

## Out of Scope (explicit)

- 不在 MVP 中重做现有分组、订阅或 API Key 绑定模型。
- 不在 MVP 中实现复杂机器学习/预测式定价。
- 不在 MVP 中改变普通用户侧排行榜展示。
- 不在 MVP 中支持迁移并移除旧分组；授权分组模式只新增/保留目标分组授权。
- 不在 MVP 中支持单个策略内不同档位分配不同目标分组；如需不同分组，可后续扩展为档位级目标分组。
- 不在 MVP 中支持同一目标分组的多策略优先级或最优惠倍率合并。

## Technical Approach

- 新增自动策略与档位的数据模型：策略保存目标分组、统计窗口、筛选条件、执行动作、执行频率、冲突处理策略、启用状态和执行时间；档位保存 Token 阈值与倍率。
- 新增自动执行归属记录：记录哪些用户配置由哪条策略写入、当前档位、上次写入值和人工接管状态，用于安全降档/清除。
- 复用现有用量日志聚合口径，按策略筛选范围聚合每个用户的窗口 Token。
- 复用现有用户专属分组倍率能力写入 `(user_id, group_id) -> rate_multiplier`。
- 手动批量统一倍率优先复用现有用户专属分组倍率写入链路，并在前后端同时校验倍率格式和选中范围。
- 授权分组模式复用现有用户 allowed groups 能力；自动清除时只清除该策略产生的授权。
- 新增调度执行器，支持按配置频率执行、手动预览、立即执行、执行锁和执行记录。
- 前端新增独立管理员页面，管理策略、档位、筛选范围、执行频率、预览结果和执行历史。

## Decision (ADR-lite)

**Context**: 需要根据近期 Token 使用量自动维护用户在某个分组下的专属倍率，并支持分组授权、降档和管理员可控执行。

**Decision**: 采用“单策略固定目标分组 + 多有序档位”的模型；同一目标分组只允许一条启用策略；策略级配置执行动作、执行频率、统计筛选范围和冲突处理策略；默认手动设置优先。

**Consequences**: 实现稳定、降档语义清晰、管理页容易理解；暂不支持同一策略内不同档位分配不同分组，也不支持同目标分组多策略优先级。
