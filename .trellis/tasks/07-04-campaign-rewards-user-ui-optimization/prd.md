# campaign rewards user ui optimization

## Goal

优化用户侧邀请活动页面的信息密度、列表可读性和移动端体验，重点解决排行榜与邀请记录列表在当前布局下需要横向滚动、无法一次看全的问题，同时保留已实现的生命周期倒计时、规则摘要、邀请状态说明和空状态引导。

## What I already know

- 用户反馈的核心问题是邀请活动用户页面细节较多，列表宽度无法一次性显示全。
- 当前用户侧页面位于 `frontend/src/views/user/CampaignRewardsView.vue`。
- 页面已包含活动 Hero、生命周期倒计时、指标卡、邀请入口、奖励拆分、规则摘要、排行榜和我的邀请记录。
- 排行榜与邀请记录当前被放在 `xl:grid-cols-2` 的双列布局中，导致每张表只拿到半屏宽度。
- 排行榜表设置了 `min-w-[620px]`，邀请记录表设置了 `min-w-[820px]`，因此双列时很容易出现横向滚动。
- 通用 `DataTable.vue` 已有桌面表格和移动端卡片两种展示能力，但邀请活动用户页目前使用手写 table，未复用该能力。
- 邀请记录表有 7 列，其中门槛、有效充值、注册时间、达标时间可以合并为更适合用户理解的复合信息。

## Assumptions

- 本轮优化优先做用户侧 `/campaign-rewards`，不改管理员侧。
- 本轮不新增后端接口，优先基于现有 `CampaignHome`、`CampaignMyData`、`CampaignInviteRecord`、`CampaignLeaderboardRow` 字段完成。
- 表格优化以“用户能快速理解自己的进度和每条邀请为什么未生效”为目标，不追求后台管理式的全字段平铺。

## Requirements

- 排行榜和邀请记录在桌面端应尽量完整显示，不应默认被双列布局压窄。
- 移动端不应依赖横向滚动读取核心信息。
- 邀请记录应减少列数，保留核心字段，并把辅助字段合并到行内详情。
- 邀请链接应比邀请码更突出，复制按钮在窄屏下不应挤压链接内容。
- 预计奖励、有效邀请、当前排名应比待审核邀请更突出。
- 活动估算类金额旁应持续提示“最终以审核结算为准”的语义。
- 刷新操作不应在已有数据时造成整页闪白或大面积跳动。

## Acceptance Criteria

- [ ] 列表区改为纵向全宽布局，排行榜和邀请记录不再在 `xl` 桌面端互相挤压。
- [ ] 邀请记录在窄屏下使用卡片式或等价的分组展示，不需要横向滚动即可看到被邀请人、状态、充值进度、关键时间和原因说明。
- [ ] 邀请记录桌面列数收敛到 4-5 列，门槛/充值和注册/达标时间合并展示。
- [ ] 当前用户排行榜行继续高亮，Top 3 有轻量视觉层级但不夸张。
- [ ] 邀请链接作为主入口，邀请码作为次级备用入口。
- [ ] 已有视图测试覆盖核心渲染、状态说明、复制按钮禁用逻辑；新增或更新测试覆盖列表重排后的关键文本。

## Out of Scope

- 不新增二维码分享。
- 不新增后端分页、筛选或排序接口。
- 不处理管理员侧活动运营控制台。
- 不改变活动生命周期计算规则。

## Proposed Implementation

1. 先调整列表区布局：将排行榜和邀请记录从双列改为纵向全宽，解决最大可见宽度问题。
2. 再压缩邀请记录信息结构：状态和说明合并、门槛和充值合并为“充值进度”、注册和达标合并为“时间线”。
3. 为移动端增加卡片式记录展示，或抽出轻量行组件，在桌面表格和移动卡片间复用格式化逻辑。
4. 优化邀请入口：链接优先、邀请码次级，复制按钮尺寸固定，避免窄屏挤压文本。
5. 优化刷新状态：已有数据时保留当前内容，仅让刷新按钮转圈；首次加载才显示整页 loading。
