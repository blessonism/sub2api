# 实施计划：抽奖活动美元用量口径

## 1. 数据库与后端模型

- 新增迁移，为活动和资格快照增加用量口径及微美元字段，并覆盖历史默认值和约束测试。
- 扩展服务模型、管理员请求、仓储扫描与 CRUD SQL；增加口径锁定业务错误。
- 在事务内实现“已有开奖批次不得切换口径”，保留其他已发布活动编辑能力。

## 2. 用量与资格计算

- 引入口径化 `LotteryUsage` 值对象和统一的门槛/阶梯次数计算。
- 将用户进度、手动报名、资格同步、参与人数和候选人快照切换到统一用量查询。
- 美元聚合使用 `FLOOR(SUM(actual_cost) * 1000000)::BIGINT`，Token 查询保持现状。
- 扩展资格 upsert、候选人及用户 API 响应，保留现有 Token 字段。

## 3. 管理端与用户端

- 扩展前端 API 类型与请求契约。
- 管理表单增加口径选择、美元门槛/阶梯输入、校验、回填、规则预览和口径化摘要。
- 用户活动中心按 Token 或美元展示当前进度、门槛和进度条；候选人管理按口径展示用量。
- 同步补齐 zh/en 下游文案。

## 4. 验证门槛

- 后端服务测试：Token 回归、美元临界门槛、阶梯次数、最大次数、模式归一化、已有批次锁定。
- 仓储测试：迁移列/约束、美元聚合 SQL、资格微美元快照、事务锁定行为。
- 前端测试：创建/编辑 payload、4 位小数转换与拒绝、两种口径的指标/规则/用户进度显示。
- 运行抽奖相关 Go 测试、前端定向 Vitest、类型检查和迁移回归测试。

## 5. 分支与发布边界

- base branch 设置为 `custom/main`，工作分支为 `feature/lottery-usd-usage-mode`。
- 当前工作区存在其他任务的未提交修改，实现阶段使用独立 worktree，禁止混入或回退现有修改。
- 本阶段只完成本地实现与验证；生产部署必须另行获得明确确认并使用 OVH 安全部署流程。
- 回滚应用时保留新增数据库列；不执行破坏性降级迁移。
