# 抽奖活动支持按美元消费计算

## Goal

让管理员创建或编辑抽奖活动时，可以在“Token 用量”和“美元消费”之间选择一种资格计算口径，并沿用现有的达标、阶梯次数、报名和开奖流程。

## Background

- 当前抽奖活动只累计 `usage_logs` 中有效请求的 Token 数：`input_tokens + output_tokens + cache_creation_tokens + cache_read_tokens`。
- 当前有效请求以 `actual_cost > 0` 判断。
- 美元模式确定使用 `usage_logs.actual_cost`：这是包含用户分组倍率影响的用户/API Key 实际扣费口径，也是余额或订阅额度实际扣减所使用的金额。
- 当前活动配置、资格快照、用户进度、管理员表单和 API 字段都以整数 Token 为单位，需要扩展跨数据库、后端和前端的契约。
- 已存在的活动必须继续按 Token 口径运行，不能因升级改变资格或抽奖次数。
- 草稿活动可以自由切换用量口径；已发布但尚未产生开奖批次的活动也可以切换，并按新口径重新同步资格。
- 活动一旦产生任何开奖批次，用量口径即锁定，避免历史资格、权重和开奖记录产生审计歧义。

## Requirements

- 活动支持选择且只能选择一种用量口径：Token 用量或美元消费。
- Token 模式保持现有统计窗口、门槛、阶梯次数和最大次数逻辑不变。
- 美元模式在相同开奖窗口内累计 `usage_logs.actual_cost`，并使用美元门槛与阶梯金额计算抽奖次数。
- 美元模式统计所有 `actual_cost > 0` 的成功消费，包括图片、按次计费等没有常规 Token 的请求。
- 创建、编辑、管理员详情和用户活动中心必须按所选口径显示正确的单位、进度与文案。
- 切换已发布且未开奖活动的口径后，后续读取和同步必须按新口径覆盖当前窗口的资格快照。
- 已存在开奖批次时，修改请求不得切换用量口径，但不影响其他仍被允许的配置编辑。
- 历史活动及迁移后的默认值为 Token 模式。
- 金额比较和次数计算必须避免浮点边界误差。
- 美元门槛和阶梯金额在管理界面以美元输入，最多允许 4 位小数；后端使用整数微美元进行比较和次数计算。
- 同步名单、自动/手动报名、参与人数、开奖候选权重必须统一使用活动选择的口径。

## Acceptance Criteria

- [ ] 管理员可创建 Token 模式或美元模式的抽奖活动，并可编辑其用量口径与对应门槛。
- [ ] 草稿及尚无开奖批次的已发布活动可以切换口径；已有开奖批次的活动切换口径会返回明确业务错误。
- [ ] 历史活动迁移后仍按原始 Token 配置计算，用户结果不变。
- [ ] 美元模式只累计同一开奖窗口内符合最终口径定义的有效消费。
- [ ] 图片、按次计费等无常规 Token 但 `actual_cost > 0` 的请求会进入美元进度，不会进入 Token 进度。
- [ ] 美元消费刚好等于门槛时获得首次资格，低于门槛时无资格。
- [ ] 管理员可以输入最多 4 位小数的美元门槛/阶梯值，超出精度或非正数时得到明确校验错误。
- [ ] 阶梯模式按 `1 + floor((当前用量 - 门槛) / 阶梯值)` 计算，并受单用户最大次数限制。
- [ ] 用户进度、资格同步、参与人数和开奖权重使用同一个数值口径，不出现 Token/美元混算。
- [ ] API、数据库迁移、后端测试和前端测试覆盖两种模式及历史兼容。

## Out of Scope

- 同一活动同时要求 Token 和美元双重达标。
- 将抽奖用量从用户余额或订阅额度中再次扣除。
- 修改现有开奖时间窗口、中奖选择或奖金发放规则。
