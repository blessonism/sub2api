# OVH mihomo 与 Sub2API 代理链路只读诊断设计

## 诊断边界

诊断覆盖四个互相独立的观察层：

1. mihomo 服务层：进程或容器、监听端口、配置加载和近期日志。
2. mihomo 出站层：宿主机通过代理访问无敏感公共端点的 HTTP/HTTPS、DNS 和出口地址。
3. 应用网络层：Sub2API 运行网络到 mihomo 地址和端口的连通性。
4. 业务选择层：Sub2API 实际使用的代理来源、目标地址和近期代理错误。

任何一层成功都不能替代下一层的验证。例如 mihomo 端口可连接，不代表当前节点可以出站；宿主机可通过 mihomo 出站，也不代表容器能访问宿主机回环地址。

## 证据流

1. 校验 SSH 目标的主机名、系统信息和当前时间，避免连接到错误服务器。
2. 盘点 `systemd`、Docker 和进程列表，识别 mihomo 的真实运行方式及配置文件路径。
3. 读取 mihomo 状态、监听和有限日志，不输出订阅 URL、认证字段或完整配置。
4. 对照宿主机直连与经 mihomo 的无凭据探测，判断故障是否位于节点、DNS、TLS 或代理协议。
5. 识别 Sub2API 容器、网络和代理地址来源，在应用网络命名空间验证目标端口。
6. 采样 Sub2API 近期有限日志，将错误时间、目标端口、错误类别与 mihomo 日志交叉关联。

## 安全控制

- 远端命令只允许读取状态、端口、配置字段名和有限日志。
- 不执行 `restart`、`reload`、`up`、`down`、`exec` 写操作、节点切换、配置更新或数据库查询。
- 不打印完整环境变量、mihomo 完整配置、订阅地址、认证信息和请求正文。
- 网络探测设置短连接和总超时，禁止压力测试、循环探测和带认证请求。
- 如果发现必须改变生产状态才能继续，立即停止并向用户说明影响范围和回滚方式。

## 判断规则

- mihomo 未运行、端口未监听或持续重启：服务层故障。
- 端口正常但经代理公共探测失败，直连成功：mihomo 节点、规则、DNS 或出站故障。
- 宿主机经代理成功，但 Sub2API 运行网络无法连接：容器地址、网络命名空间或监听绑定故障。
- 应用能连接 mihomo，但日志显示特定业务代理记录、认证或代理协议失败：Sub2API 业务代理配置故障。
- 四层均正常且日志无相关错误：标记为暂未复现，继续以失败时间和请求标识缩小范围，不直接判定系统正常。

## 变更与回滚

本任务不执行生产变更，因此没有运行时回滚。后续若建议重启、切换节点或修改配置，必须创建明确的变更步骤、备份和回滚方案，并再次取得用户确认。
