# 排查 OVH mihomo 与 Sub2API 代理链路

## Goal

通过只读 SSH 证据判断故障位于 OVH 上的 mihomo 服务、mihomo 当前出站节点、Sub2API 到 mihomo 的连接链路，还是 Sub2API 业务代理选择与请求处理逻辑，并给出可复核的根因判断和修复建议。

## Background

- OVH SSH 别名为 `ovh`，目标为 `15.204.94.115:20002`，用户为 `root`。
- 生产部署目录、mihomo 运行形态和代理端口必须以远端只读盘点为准，不使用本地示例配置推断。
- 现有 `07-11-ovh-sub2api-502-ux-audit` 任务已约束生产排查不得修改配置、重启容器、部署或读取敏感请求数据；本任务沿用该边界并聚焦 mihomo。
- 必须区分宿主机系统代理、Sub2API 容器环境代理和 Sub2API 数据库中的业务代理记录，不能把三者视为同一配置。

## Requirements

- 确认 mihomo 的运行方式、进程或容器状态、监听地址、端口、启动时间和近期异常日志。
- 使用不携带凭据和用户数据的请求，分别验证 OVH 宿主机直连、宿主机经 mihomo、Sub2API 运行网络到 mihomo 的可达性和出站结果。
- 检查 Sub2API 当前生效的代理连接配置来源，只输出变量名、地址类型、端口和脱敏后的目标，不输出代理认证信息、API Key、Cookie、数据库内容或用户请求正文。
- 检查 Sub2API 近期日志中与代理连接失败、超时、连接拒绝、TLS、DNS、502、节点切换和 mihomo 端口相关的有限时间窗口证据。
- 将结论分为 mihomo 服务故障、mihomo 节点/出站故障、Sub2API 到 mihomo 的链路故障、Sub2API 业务代理配置故障或暂未复现，并标注证据和置信度。
- 全程只读；任何重启 mihomo、切换节点、修改配置、重建容器或执行带凭据的业务探测都必须另行获得明确确认。

## Acceptance Criteria

- [x] 明确 mihomo 是否存活、监听是否正常，以及近期是否存在崩溃、重启或配置加载错误。
- [x] 明确 OVH 宿主机通过 mihomo 的基础 HTTP/HTTPS 出站是否成功，并与直连结果对照。
- [x] 明确 Sub2API 运行环境能否连接 mihomo，以及当前应用是否实际引用该代理地址。
- [x] 给出近期 Sub2API 代理相关错误的日志关联结果；无命中时说明时间窗口和可观测性限制。
- [x] 输出按优先级排序的根因判断、影响范围和修复建议，明确哪些操作会改变生产状态。
- [x] 排查过程不修改生产服务、配置、容器、数据库、DNS、防火墙或流量。

## Out of Scope

- 重启或重载 mihomo。
- 切换代理节点、订阅或规则集。
- 修改 Sub2API 代理记录、容器环境变量或生产配置。
- 使用真实 API Key、账号凭据或用户请求进行上游业务探测。
- 部署代码、构建镜像或修改数据库。
