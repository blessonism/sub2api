# 邀请活动历史有效邀请折算 - 技术设计

## 设计目标

在不改变活动期邀请事件链路和奖金池注入规则的前提下，为每个活动生成历史有效邀请快照，并以定点小数把历史人数折算进排行榜及结算。所有派生结果必须可重算、可审计、幂等且不受活动激活后的源数据变化影响。

## 数据模型

### 活动配置

在 `campaign_config_versions` 增加 `historical_invite_ratio NUMERIC(12,8) NOT NULL DEFAULT 0`，内部语义为 `0..1`。该字段进入创建、复制、读取、配置版本和前后端 DTO；发布后遵循现有不可变规则。

### 历史邀请快照

新增 `campaign_historical_invite_snapshots`：

- `campaign_id`、`config_version_id`、`inviter_user_id`、`invitee_user_id`；
- 邀请关系建立时间、快照截止时间（固定为 `campaign.start_at`）；
- 充值门槛快照、历史充值总额、折算比例快照；
- `qualified_at`（历史累计首次达到门槛的可得时间；旧数据无法可靠推导时使用最后一笔纳入充值时间）；
- `created_at`；
- 唯一约束 `(campaign_id, invitee_user_id)`。

在 `campaigns` 增加历史快照完成时间或等价完成标记。快照行和完成标记必须在同一事务提交；完成标记存在时直接返回，保证重试幂等且不暴露半成品。快照成员、充值金额和截止时间不可变；折算比例仅允许在冻结或最终结算前随活动编辑事务化调整。

### 小数次数

- 数据库中的折算次数、榜单快照有效次数改用 `NUMERIC`，避免二进制浮点累计误差。
- Go 领域计算使用 `decimal.Decimal`；只在 JSON 边界输出前端可消费的数值表示。不得在仓储扫描、排序、差距或奖励计算阶段转为整数。
- 保留活动期原始人数、历史原始人数和人工调整值，折算后总数是可验证的派生值。

## 历史充值归集

以 `campaign.start_at` 为严格上界，按被邀请人归集：

1. `payment_orders` 中 `order_type = 'balance'` 且成功完成的订单，采用可靠成功时间和订单金额；
2. `redeem_codes` 中已使用且类型为余额的记录，采用 `used_at` 和面值；
3. 若兑换码是已完成支付订单的 `recharge_code`，仅保留支付订单来源，避免双计；
4. 其他余额变化、订阅订单和活动开始后的充值不进入历史累计。

邀请关系来自 `user_affiliates`，要求其关系建立时间早于 `start_at`。历史累计金额达到已发布配置的门槛后，才写入合格快照。

## 激活与并发

### 立即发布为 active

发布事务先锁定活动、生成历史快照并写完成标记，再将状态切为 `active`。任一步失败都回滚，活动不可处于“已激活但快照缺失”的状态。

### warmup 自动激活

把当前 `GetActiveCampaign` 中隐式的 `warmup -> active` 更新收敛为带事务的激活动作：锁定候选活动、生成快照、写完成标记、切换状态。并发调用依赖行锁、完成标记和唯一约束保证单次生效。

暂停/恢复及取消冻结回到 `active` 时复用同一幂等快照检查，不重新生成历史数据。

## 排行榜与结算

排行榜聚合拆分为：

- 活动期有效人数：现有 `campaign_invite_records.status = 'effective'`；
- 历史有效人数：历史快照表按邀请人计数；
- 折算次数：历史人数乘快照比例；
- 最终有效次数：活动期人数 + 历史折算次数 + 人工调整，并以 `GREATEST(..., 0)` 限制下界。

历史充值额不并入本次活动的 `invitee_recharge_amount_cents`，避免影响奖金池贡献口径。排名、贡献奖励平方根权重、名次差距、实时预估、冻结快照和最终结果全部读取同一折算后次数。

## API 与页面

管理端创建/复制/详情接口增加历史折算比例。榜单行和“我的数据”增加：

- `activity_valid_invite_count`；
- `historical_valid_invite_count`；
- `historical_weighted_invite_count`；
- `valid_invite_count`（折算后总数，允许小数）。

管理端创建表单使用百分比输入，提交时规范化为后端约定的小数比例。用户端指标与榜单统一使用小数格式，并展示历史折算组成；中英文文案同步放在 locale overlay。

## 兼容与迁移

- 新字段默认比例为 `0`，已有活动不会自动纳入历史邀请。
- 已有整数榜单快照迁移到 NUMERIC 后数值不变。
- 不为已进入 auditing/publicizing/pending_payout/paid 的活动补历史快照。
- 删除活动时历史快照随活动级联删除，并计入删除影响统计。

## 风险与回滚

- 最大风险是历史充值双计和激活并发产生不完整快照；通过来源去重查询、事务完成标记和唯一约束防护。
- 若上线后需停用，管理员可将新活动比例设为 `0`；代码回滚前保留新增列和快照表，避免旧二进制因破坏性回滚失败。
- 迁移只做向前兼容的新增/类型扩展，不删除历史审计数据。
