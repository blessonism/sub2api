# 邀请活动历史有效邀请折算 - 实施计划

## 1. 数据库与领域契约

- 新增迁移：配置比例、历史快照表、完成标记及榜单小数字段/索引/约束。
- 扩展 Campaign 配置、榜单、参与者、快照与 API DTO，统一使用定点小数语义。
- 更新创建、复制、配置版本读取与校验，默认比例为零。

## 2. 历史快照与激活流程

- 在仓储实现按活动开始时间归集历史邀请和有效余额充值，明确支付订单与充值码去重。
- 实现事务化、并发安全、可重复调用的历史快照生成。
- 将立即发布、warmup 自动激活、暂停恢复和取消冻结接入同一快照保证逻辑。

## 3. 排行榜与奖励计算

- 重构榜单 SQL，分别聚合活动期人数、历史人数、折算次数与人工调整。
- 让实时榜单、个人统计、名次差距、贡献权重、榜单冻结和最终结算完整保留小数。
- 保持历史充值不注入奖池、不进入活动期有效充值总额。

## 4. 管理端与用户端

- 扩展管理端 API 类型和创建/复制/详情表单，支持 `0%..100%` 比例配置与校验。
- 扩展用户端 API 类型、指标、榜单和邀请明细展示，清晰展示活动期与历史折算构成。
- 同步简体中文和英文 locale overlay，避免硬编码业务文案。

## 5. 验证与评审

- 后端定向测试覆盖来源去重、门槛边界、时间上界、幂等/并发激活、小数排序、人工调整、奖池隔离和结算一致性。
- 前端定向测试覆盖比例输入、API payload、小数格式和历史构成展示。
- 执行后端相关包测试（单次命令限制 60 秒）、前端 typecheck 与相关 Vitest。
- 使用 `trellis-check` 复核跨层契约、迁移安全和下游 fork 边界。

## 回滚点

- 数据迁移完成后不做破坏性降级；代码回滚保留新增列和快照表。
- 激活流程变更必须在任何生产部署前验证旧比例 `0` 的回归路径。
