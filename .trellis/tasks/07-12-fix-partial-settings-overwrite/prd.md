# 修复局部设置覆盖全部基础配置

## Goal

阻止任何局部设置请求通过全量系统设置接口把未提交字段覆盖为空值或零值，并修复 Token 排行榜设置的危险调用链。

## Requirements

- Token 排行榜设置必须使用仅能写入排行榜相关键的独立接口。
- 通用系统设置更新接口收到不完整请求时必须拒绝写入，不能依赖 Go 零值补齐。
- 前端 API 类型必须区分全量设置保存与排行榜局部保存，禁止继续暴露 `Partial<SystemSettings>` 的全量更新入口。
- 保留密码、密钥等现有“留空不变”行为，不在日志或错误响应中暴露敏感值。
- 不引入生产数据库迁移，不修改现有配置值。

## Acceptance Criteria

- [ ] 排行榜设置接口只改变 `token_leaderboard_common_group_id` 与 `token_leaderboard_tier_tooltip`。
- [ ] 两字段请求发送到通用系统设置接口时返回 400，且数据库零写入。
- [ ] 基础设置页的完整保存仍可正常工作，敏感字段留空时保留原值。
- [ ] 后端与前端回归测试覆盖接口路径、请求完整性和未修改字段保持不变。

## Notes

- 事故证据：Token 排行榜页面只提交两个字段到 `PUT /api/v1/admin/settings`，后端将未提交字段解码为零值并整批写回。
- 本任务仅修改代码和测试；生产部署另行确认。
