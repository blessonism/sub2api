# 公告邮件群发

## Goal

管理员可以把当前生效的站内公告手动群发给命中公告投放条件的正常用户，并查看持久化进度、逐用户结果及重试失败项。

## Requirements

- 群发必须由管理员对已保存且当前生效的公告手动触发，并经过收件人数确认。
- 收件人复用公告的订阅与余额投放条件，只包含正常、未删除、具有真实有效邮箱的用户，并排除现有 `.invalid` 合成邮箱。
- 每个公告最多创建一个群发任务；已成功投递的用户不得主动重复发送，失败项可以重复重试。
- 群发任务保存发送时的标题、HTML 正文、收件人邮箱及逐用户投递结果，之后编辑或归档站内公告不改变快照。
- 群发开始后禁止删除公告，但允许编辑和归档。
- 后台发送必须异步、持久化并可在进程重启后恢复；单次群发按最多 1 万名收件人设计。
- 邮件内容由公告 Markdown 安全渲染为带站点品牌的 HTML；不得执行或透传原始 HTML/脚本。
- 本功能只用于系统通知，不包含营销退订、定时自动发送或独立邮件正文编辑。

## Acceptance Criteria

- [x] 管理员可以查看可发送人数，确认后创建唯一群发任务；草稿、未开始、已结束、已归档或 SMTP 未配置时均被拒绝。
- [x] 群发仅快照命中条件的正常真实邮箱用户，零收件人时不创建任务。
- [x] 管理页展示总数、待发送、成功、失败及分页投递明细，运行中自动刷新。
- [x] 失败重试只恢复失败投递，成功项保持不变；正常并发和重复请求不会重复创建或发送成功项。
- [x] Worker 使用数据库租约恢复中断任务，投递结果和汇总计数保持一致。
- [x] 已存在群发任务的公告删除返回稳定的 409 业务错误。
- [x] 中英文界面、API 类型、迁移、服务、仓储、Worker 和前端交互均有对应验证。

## Constraints

- 基线为 `custom/main`，开发分支为 `feature/announcement-email-broadcast`。
- 使用现有 SMTP 逐封发送，默认 3 个数据库 Worker，不接入第三方批量邮件服务。
- SMTP 不支持幂等键；进程在 SMTP 成功与数据库落库之间崩溃时可能产生极少量重复邮件。
- 数据库变更只新增表，应用回滚时保留审计数据。
