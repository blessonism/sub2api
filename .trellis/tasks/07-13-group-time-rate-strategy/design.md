# 技术设计

## 数据模型

- `groups.time_rate_priority` 保存 `schedule_first`、`user_first` 或 `proportional`，默认 `schedule_first`。
- `groups.time_rate_periods` 使用 JSONB 保存由分组整体拥有的小型配置数组，元素为 `start_time`、`end_time`、`rate_multiplier`、`visible_rate_multiplier`、`enabled`。
- 时间匹配与优先级计算集中在 service 层纯函数中，仓储、handler 与计费入口不重复实现规则。

## 数据流

- 管理员通过现有 `PUT /admin/groups/:id` 部分更新两个策略字段；保存前由后端统一校验并按开始时间排序。
- 计费先解析用户专属真实倍率及其来源，再应用当前时间段策略；最终倍率再传给文本、图片、视频及网页搜索计费。独立倍率分支绕过分时倍率。
- 用户侧 `/groups/rates` 与套餐/渠道响应在服务端按请求时刻计算当前可见倍率，不返回 `time_rate_periods`。
- API Key 认证缓存快照携带策略数组与优先模式，避免缓存路径丢失计费配置。

## 迁移

- 先增加新字段并把有效旧高峰规则转换为单个启用时间段：真实目标为基础真实倍率乘旧系数，可见目标为基础可见倍率乘旧系数，模式为 `proportional`。
- 完成回填后删除旧高峰四字段；代码生成物同步更新，不保留双轨兼容逻辑。

## 边界

- 开始时间仅允许 `00:00` 至 `23:59`；结束时间允许 `00:01` 至 `24:00`，且必须严格晚于开始时间。
- 仅检查启用时间段之间的重叠；所有行仍必须具备合法时间和非负倍率。
- 比例模式基于分组基础真实/可见倍率计算；若历史脏数据导致分母不大于零，安全降级为时间段目标值。
