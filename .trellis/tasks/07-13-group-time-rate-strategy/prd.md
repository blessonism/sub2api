# 分组分时倍率策略

## Goal

为所有分组提供按服务器时区每日循环的多时间段倍率策略，并通过分组列表独立弹窗管理。命中策略时，真实倍率与用户可见倍率按管理员选择的优先模式处理；实际计费与用户侧当前倍率保持一致。

## Requirements

- 分组列表每行增加“分时倍率”操作，弹窗支持添加、删除、启停、撤销和保存时间段。
- 时间段包含开始时间、结束时间、真实目标倍率、用户可见目标倍率；新建时两种倍率默认一致，随后可独立编辑。
- 时间段按服务器时区每日重复，采用左闭右开区间；结束时间允许 `24:00`，不允许跨午夜，启用区间不得重叠，允许留空档。
- 分组级支持 `schedule_first`、`user_first`、`proportional` 三种专属倍率处理模式；真实与可见倍率分别执行同一模式。
- 分时策略适用于标准和订阅分组，影响所有继承分组倍率的计费类型；独立图片/视频倍率不受影响。
- 普通用户接口不暴露完整策略，只返回请求时刻的当前可见倍率；管理员接口可读写完整策略。
- 删除旧单时段高峰配置 UI 与字段；迁移将已启用旧规则转换为一个 `proportional` 时间段，保持升级时计费结果。
- 目标倍率允许为 `0`；不增加星期、节假日、日期范围、历史、审批或定时发布能力。

## Acceptance Criteria

- [ ] 管理员可在分组列表打开分时倍率弹窗并完整管理策略，未保存修改可撤销且关闭前有丢失确认。
- [ ] 后端拒绝非法时间、非法优先模式、负倍率以及启用时间段重叠；空档回退原倍率。
- [ ] 三种优先模式在真实倍率和可见倍率上均符合约定，并正确处理无专属、真实专属和可见专属倍率。
- [ ] 文本及其他继承分组倍率的计费使用当前分时倍率，独立图片/视频倍率保持原值。
- [ ] 普通用户页面只显示当前可见倍率，响应不包含完整时间段策略。
- [ ] API Key 认证缓存快照保留策略，分组更新后缓存失效。
- [ ] 旧高峰规则迁移后原时间段内实际与可见倍率不突变，旧字段及旧 UI 不再保留。
- [ ] 后端与前端相关测试、类型检查和静态检查通过。
