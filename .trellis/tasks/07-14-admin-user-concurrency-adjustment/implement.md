# 管理员一键调整用户并发 - 实施计划

## 1. 后端原子下限更新

- 扩展批量并发请求校验，使 `mode=floor` 只接受大于等于 `1` 的整数。
- 在 UserRepository 增加批量提高并发下限的方法，使用 `GREATEST` 与未删除条件完成原子更新。
- 在 AdminService 的批量并发分支接入 `floor`，保留现有 `set` / `add` 行为和缓存失效流程。
- 添加最小后端测试，覆盖低值提升、高值不降低和非法下限拒绝。

## 2. 管理端操作入口

- 在 `adminAPI.users` 增加全量提高并发下限方法，返回 `affected`。
- 在用户列表工具栏增加“统一并发下限”按钮，复用 `ConfirmDialog` 承载正整数输入和范围说明。
- 成功后关闭弹窗、提示实际提升数量并刷新列表；失败时提示后端错误且不修改现有列表。
- 同步补齐简体中文和英文文案。

## 3. 验证与审查

- 运行目标后端单元测试，确认 SQL 和 Handler/Service 分支行为。
- 运行用户列表目标 Vitest，覆盖合法提交、非法输入和成功刷新。
- 运行前端类型检查与受影响包的 Go 测试，单次后台测试最长不超过 60 秒。
- 检查 diff 未混入当前工作区其他任务改动，且任务仍以 `custom/main` / `feature/admin-user-concurrency-adjustment` 为分支边界。

## 风险点

- `UserRepository` 是共享接口，新增方法时必须同步现有测试 stub，避免编译失败。
- 当前工作区已有大量其他任务未提交改动；只修改本任务明确列出的文件，不切换或清理分支。
- 全量操作会失效目标用户认证缓存；沿用现有批量实现，不额外引入任务队列。

## 验证记录

- 目标 Repository、Handler、前端 API/视图与 i18n 测试通过，前端类型检查和受影响文件 ESLint 通过。
- Repository 全包测试存在本分支基线中的无关 SQL mock 失败，并在 60 秒上限终止；本任务目标 Repository 测试单独通过。
