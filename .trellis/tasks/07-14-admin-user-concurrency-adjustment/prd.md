# 管理员一键调整用户并发

## Goal

让管理员能从用户管理页一次性提高所有用户的并发下限，无需逐个编辑账号，同时保证已有更高并发不会被降低。

## Background

- 用户管理页当前在编辑用户弹窗中支持修改单个用户的 `concurrency`，但需要打开弹窗后再提交。
- 后端已经提供 `POST /api/v1/admin/users/batch-concurrency`，支持对指定用户 ID（最多 500 个）或全部用户执行 `set` / `add` 两种并发调整模式。
- 前端 `adminAPI.users` 尚未封装该批量接口，`UsersView` 也没有用户选择或批量并发入口。
- 当前工作区位于其他功能分支且存在未提交改动；本任务只记录以 `custom/main` 为基线的目标分支，不在规划阶段切换分支或覆盖现有改动。

## Requirements

- 管理员能够从用户管理页更直接地调整用户并发。
- 提供面向所有用户的一键设置入口；输入值作为并发下限，而不是覆盖值。
- 目标并发下限由管理员每次在操作弹窗中手动输入，不提供固定快捷档位。
- 执行后仅提升当前并发低于目标值的用户，已经高于或等于目标值的用户保持不变。
- “所有用户”指全部未软删除账号，包括已禁用用户和管理员账号。
- 目标值必须是大于等于 `1` 的整数；沿用现有用户并发规则，不额外设置上限。
- 调整弹窗必须明确说明作用范围和“只升不降”语义，管理员确认后才执行。
- 使用现有用户并发字段和后端更新链路，不新增数据库字段。
- 成功后刷新受影响用户数据，并提供明确的成功或失败反馈。

## Acceptance Criteria

- [x] 管理员无需进入完整用户编辑流程即可发起并发调整。
- [x] 以目标值 `N` 执行全量调整后，所有目标用户的并发均不低于 `N`，原本高于 `N` 的并发值不变。
- [x] 小于 `1`、非整数或空目标值不能提交，后端也拒绝非法值。
- [x] 操作入口和确认弹窗明确提示会处理全部未删除账号，包括已禁用用户和管理员账号。
- [x] 操作成功后，用户列表显示最新并发值。
- [x] 成功反馈包含实际提升的用户数量；操作失败时保留当前页面数据并展示错误反馈。
- [x] 关键交互有最小必要的自动化测试覆盖。

## Out of Scope

- 不调整账号（Account）并发配置。
- 不修改用户并发限流的运行时实现。
- 不新增数据库迁移。
- 不提供按筛选结果、选中用户或固定快捷档位调整。
- 不改变现有单用户编辑和批量 `set` / `add` 语义。
