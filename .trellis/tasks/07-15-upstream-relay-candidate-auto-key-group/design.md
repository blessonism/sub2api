# 技术设计

## 边界与数据流

1. 上游 `/api/v1/keys` 解析器读取 `group_id`（兼容字符串和数字），扩展 Key 选项 DTO；分组名称由现有分组快照按 ID 解析，不在候选表中重复存储。
2. 候选用量刷新先读取当前 Key 列表，建立 `api_key_id -> current_group_id` 映射；每个候选绑定按该映射把 `/usage/stats?api_key_id=` 的结果聚合到当前分组。
3. 未找到 Key 或 Key 没有当前分组时，为该候选生成稳定 issue，跳过该 Key，不回退到旧的手动分组，避免静默错误归属。
4. 前端选择 Key 后使用返回的 `group_id` 回填候选分组；没有该字段时保留现有手动输入回退。编辑已有候选时，当前 Key 的分组只改变表单值，保存才持久化。
5. 候选列表按连接器批量读取当前 Key 分组，并在响应内用当前分组快照覆盖候选的有效分组/倍率/今日用量；该过程只修改内存 DTO。推荐生成使用同一解析逻辑，无法解析的候选清空有效快照并进入排除项，不阻断其他有效候选。
6. 动态分组只用于当日刷新。历史日期定格继续按候选保存分组归属，避免用今天的 Key 分组重写过去数据。
7. 用量请求仍按 Key ID 缓存；增加已累计 Key 集合，使重复候选绑定不会重复叠加同一份完整用量。

## 兼容与风险

- 不改数据库结构和候选绑定字段；旧候选仍可显示、编辑。
- 上游 Key 列表接口若暂不提供 `group_id`，刷新结果会明确提示当前 Key 无法归属，其他 Key 仍继续刷新。
- 分组 ID 统一在边界转换为字符串，与现有快照/候选契约一致。

## 回滚

- 变更集中在上游 Key 解析、用量聚合和候选表单类型/回填；可整体回退，不涉及迁移或运行时数据修复。
