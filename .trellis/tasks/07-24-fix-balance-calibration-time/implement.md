# 实施计划

## Steps

1. 新增迁移，为校准日分摊增加 6 位小数余额差额，并按 Token 原始用量权重回填可推断的历史组合校准。
2. 扩展仓储创建流程：生成确定性的余额日分摊，支持 Token 差额为零但余额非零的组合请求，并返回日余额差额审计字段。
3. 将单用户、批量用户及排行榜余额校准汇总统一改为“日分摊优先、balance-only 主表回退”的时间过滤口径。
4. 补充仓储测试，覆盖跨日正负分摊精确求和、确定性余数、历史日期过滤、总计和 balance-only 回退。
5. 增加独立消费校准请求、事务内范围总消费计算与审计字段，消费差额反向更新钱包并复用每日余额分摊。
6. 前端增加消费校准控件与范围总消费预览，提交范围、时区和目标/增减值。
7. 补充消费目标值、正负消费差额、余额不足和范围消费不可为负的回归测试。

## Validation

- `cd backend && go test ./internal/repository ./internal/service`
- `cd backend && go test ./internal/handler/admin`
- `git diff --check`

## Risk And Rollback

- 风险集中在余额消费统计重复计入；查询必须用 `NOT EXISTS` 排除已有日余额分摊的主记录。
- 金额分摊只用整数百万分之一单位计算，禁止浮点权重计算。
- 若定向测试失败，先回退统计查询与创建逻辑；迁移新增的可空列可保留，不影响旧路径。
