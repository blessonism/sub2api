# 技术设计

## 分支与引用边界

- `custom/main`：只作为下游同步基线，本次不移动指针。
- `upstream/main`：fetch 后固定的官方同步源，预检和合并使用同一对象。
- `sync/upstream-20260907`：本次同步工作分支，从最新 `custom/main` 创建。
- `origin`：只更新本地远程引用，不推送。

## 数据流

1. 记录当前分支、提交、工作树路径和未提交内容。
2. 禁用 tag 跟随分别 fetch 两个 remote，读取新的 `upstream/main` OID。
3. 对 `custom/main` 与 `upstream/main` 运行同步预检，识别重叠路径和高风险能力。
4. 在同步分支以 `--no-commit` 方式合并，先检查冲突和差异，再决定是否创建 merge commit。
5. 生成同步检查计划并执行命中的 lane；对环境不可用项如实标记未验证。

## 工作树保护

当前已有的已跟踪修改与未跟踪内容不属于同步范围。切换分支/合并前先确认 Git 没有路径碰撞；如必须清理工作树，使用可恢复的 stash 或外部备份，不删除或重置用户内容。

## 兼容与回滚

- 合并未提交时使用 `git merge --abort` 返回同步分支合并前状态。
- 合并提交后只在同步分支使用 `git revert -m 1 <merge-commit>`，不改写共享分支历史。
- `custom/main` 如需后续合入，另行走 PR 和完整 CI。

## 风险与取舍

- 上游与二开可能同时修改核心路径，文本无冲突不代表行为兼容；重点复核路由、DTO、仓储生产者和前端动态 key。
- 为避免未经确认的高风险提交，先使用 `git merge --no-commit`；是否完成 merge commit 需要用户另行明确确认。
