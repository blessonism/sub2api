# 用户端 V1 渠道监控卡片改造

## 目标与背景
以用户参考图为目标，普通用户可在紧凑卡片中查看渠道可用性、当前展示倍率和主模型使用体验。现有 V1 提供主动探测、7/15/30 日可用率、最近 60 次探测及可选配额；缺少稳定分组 ID 和用量指标。

## 要求
- R1：顶部平台图标、名称、主模型、三位小数倍率；状态与主模型最近探测相对时间；响应时间/可用率/24h 缓存三列；近 5m 平均 TPS；最近 60 次探测条；整卡打开原详情。
- R2：无外边框、轻柔阴影（按用户最新反馈）、响应式、深浅主题、中英文、骨架与空状态；保留限流/拥挤、降级、失败、配额、自动刷新和窗口切换。
- R3：可选 group_id，管理端新增/编辑/复制完整持久化；选择本站 API Key 自动带入分组；存量不按 group_name 自动绑定。
- R4：关联分组 + 主模型，跨用户的 usage_logs 数据；请求模型归一化与 V2 一致。缓存率 = 最近 24h cache_read / (input + cache_creation + cache_read)；TPS = 最近 5m AVG(output_tokens*1000/duration_ms)，与运维有效文本请求和完整耗时口径一致。
- R5：使用当前用户最终可见倍率与现有分组可用权限；共享缓存只含统计；无绑定、无数据或统计故障均显示未知，保留探测结果；纯配额不查询模型统计。
- R6：批量查询、30 秒缓存、并发合并、2 秒超时；生成速度不受 RPM/TPM 规模隐藏开关影响。

## 验收
- AC1 对应 R1/R2：360/768/1440px、深浅主题、长名称、缺失数据无溢出；卡片点击/状态语义/7/15/30d/配额行为正确。
- AC2 对应 R3：真实 PostgreSQL 验证绑定/解绑/复制与旧行兼容。
- AC3 对应 R4：真实 SQL 验证主模型/时间窗口/无效样本过滤，0 缓存与未知区别正确。
- AC4 对应 R5/R6：服务和 API 验证倍率、权限、缓存、并发、失败降级；类型/i18n/lint/定向测试通过。

## 不包含
V2 页面改造、变更探测引擎、生产部署。
