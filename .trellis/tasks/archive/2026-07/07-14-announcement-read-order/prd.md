# 公告按阅读时间排序

## Goal

管理员打开公告的“已读情况”弹窗时，优先看到最近阅读该公告的用户，尚未阅读的用户排列在已读用户之后。

## Background

- 当前弹窗默认按用户邮箱升序展示，并在用户分页完成后才查询当前页的阅读时间。
- 阅读时间来自 `announcement_reads.read_at`，记录用户首次阅读公告的时间。
- 排序必须在分页前完成，否则只能保证单页内部有序，无法保证后续页面的全局顺序。

## Requirements

- “已读情况”列表默认按阅读时间倒序排列。
- 有阅读时间的用户排在前面，阅读时间越近越靠前。
- 未读用户统一排在所有已读用户之后。
- 阅读时间相同或均未读时使用稳定的用户 ID 顺序，避免翻页时记录漂移。
- 搜索、分页以及现有邮箱、用户名、余额排序能力保持可用。

## Acceptance Criteria

- [x] 默认打开“已读情况”弹窗时，跨分页结果满足：已读用户按 `read_at` 从最近到最早排列，随后才出现未读用户。
- [x] 阅读时间相同或均未读的用户顺序稳定。
- [x] 管理员仍可搜索用户，并可切换现有可排序列。
- [x] 后端针对默认参数和数据库排序规则有可运行的回归测试。

## Out of Scope

- 不调整用户侧公告铃铛中的公告排列顺序。
- 不改变“首次已读时间”的记录语义。
